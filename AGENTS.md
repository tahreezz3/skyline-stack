# AGENTS.md: how to work on this project

This file is for AI agents (any model, any session) and new human teammates.
The project is designed so that **many sessions can work at the same time
without interrupting each other**, and so that any session can pick up where
another stopped. Follow this protocol exactly.

## 1. Catch up (5 minutes, in this order)

1. `python3 tools/dashboard.py` then read `coordination/DASHBOARD.md`.
   It tells you the current checkpoint, which tasks are free, which are claimed, and what humans owe us.
2. Read the latest checkpoint file in `coordination/checkpoints/` (highest number).
3. Read the 2–3 most recent files in `coordination/sessions/`.
4. Skim `docs/00_VISION.md` and `docs/04_ROADMAP.md`. Read `docs/02_ARCHITECTURE.md` before touching code.
5. Run `tools/check.sh`. If it fails on a clean checkout, fixing that is your first task.

## 2. Pick and claim a task

- Tasks live in `coordination/tasks/T-XXXX-slug.md`, one file per task, with a frontmatter header.
- Pick a task with `status: todo` whose `depends` are all `done` and whose `human` requests are delivered
  (the dashboard lists these as **Ready**). Prefer the lowest milestone, then priority P0 > P1 > P2.
- **Claim it** by editing only that task file: `status: in-progress`, `owner: <your handle>`,
  `claimed: <ISO date-time>`, `updated: <date>`. Handle format: `<model-or-name>-<short-random>`, e.g. `opus55-k3f9`.
- If `git` is in use, commit the claim on its own (`claim T-0101`) before starting, so parallel sessions see it.
- A claim older than **48 hours** with no `updated` change is stale; you may take it over. Note the takeover in the task's Log section.
- Never edit another session's in-progress task except to add a line to its Log.

## 3. Work rules

- **Stay inside your task's scope.** Found something else? Create a new task with `python3 tools/new_task.py` instead of doing it.
- **Rules vs presentation.** Game rules go in `game/scripts/core/` as plain, deterministic, node-free scripts with tests.
  Scenes only render and forward input. See `docs/adr/ADR-0004-rules-presentation-split.md`.
- **Numbers live in `game/config/*.json`**, never hard-coded. Document new fields in `docs/03_DATA_SPEC.md`.
  Balance changes: run `game/tools/sim_balance.gd` before and after, and log them in `docs/balance/TUNING_LOG.md`.
- **Every rule change gets a test** in a `game/tests/test_<area>.gd` suite (see `docs/08_TESTING.md`). `tools/check.sh` must pass before you mark a task `review` or `done`.
- **Clean room.** Never copy files, text, art, audio or code from `../extracted/` or any other game.
  Use it only to read how something behaves. `tools/cleanroom_check.py` enforces part of this. Read `docs/07_LEGAL_CLEANROOM.md`.
- **Need something from a human** (art, audio, a decision, an account)? Don't block or wait in chat. Add an entry to
  `HUMAN_NEEDED.md` (format at the top of that file), reference its `HR-XXXX` id in your task's `human:` field,
  and use a placeholder so work can continue.
- **Architecture decisions** that others must follow get an ADR in `docs/adr/` (copy `ADR-TEMPLATE.md`).
- Keep files you didn't need to touch untouched. Small, focused changes merge cleanly in parallel.

## 4. Finish

1. Tick the acceptance criteria in the task file, set `status: done` (or `review` if a human must look), fill the Log.
2. Run `tools/check.sh` (it also regenerates the dashboard).
3. Write your session log: `coordination/sessions/YYYY-MM-DD_<handle>_<slug>.md` (copy `coordination/sessions/TEMPLATE.md`).
   One file per session, so parallel sessions never conflict.
4. If your work completes a milestone's exit criteria, write the next checkpoint file
   (`coordination/checkpoints/CP-XXX-name.md`, copy the template) and, if using git, tag it `cp-XXX`.
5. If using git: one commit per task, message `T-XXXX: <summary>`.

## 5. Files you must not hand-edit

- `coordination/DASHBOARD.md` and `coordination/dashboard.html` are generated by `tools/dashboard.py`.
- `game/.godot/` is the engine cache (ignored by git).

## 6. Useful commands

```bash
tools/check.sh                                                     # everything
godot --headless --path game --script res://tests/run_tests.gd     # rule tests only
godot --headless --path game -- --autoplay --seconds=60            # smoke test: bot plays one round
godot --path game --write-movie /tmp/f.png --fixed-fps 30 --quit-after 600 -- --autoplay   # capture frames to look at
godot --path game --write-movie /tmp/t/f.png --fixed-fps 10 -- --tour                       # capture every screen
python3 tools/new_task.py --title "..." --milestone M1             # create a task with the next free id
python3 tools/dashboard.py                                         # regenerate dashboard
python3 tools/task.py claim T-0101 --owner <handle>                # claim (also: status, done, log, tick)
```
